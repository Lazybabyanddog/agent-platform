1. 项目概述

1.1 建设背景

公司不同业务线需要构建各自的智能 Agent。若每条业务线独立建设模型接入、工具调用、RAG、任务执行和监控，会产生重复建设、能力孤岛、权限难统一、运行质量难衡量等问题。因此建设统一 Agent 中台，为业务系统提供标准化的 Agent 创建、配置、发布、调用和治理能力。

1.2 建设目标

统一构建通过 Agent、Prompt、模型、工具、知识库和编排能力配置业务 Agent。
统一运行通过共享 Runtime 执行不同租户的 Agent，支持同步与异步任务。
统一治理提供租户隔离、权限、配额、审计、敏感信息和成本治理。
统一度量对 Agent、RAG、工具调用、执行轨迹和模型输出进行评估与观测。

1.3 目标用户

用户角色主要诉求
平台管理员管理租户、平台资源、模型供应商、全局策略和平台运行状况。
租户管理员管理本租户成员、角色、资源授权、配额和业务配置。
Agent 开发者创建 Agent、配置 Prompt/模型/工具/知识库、编排、调试、评估和发布。
业务调用方通过 API/SDK 调用 Agent，提交任务并获取执行结果。
运维与审计人员排查失败、查看运行轨迹、成本、调用日志和审计记录。

1.4 产品范围

本期定义以下 12 个功能模块。业务系统自身的业务页面、业务数据库、企业统一身份源和具体模型厂商服务不属于中台内部建设范围，但需要通过标准接口集成。

2. 总体架构与模块关系

架构决策：多租户（Multi-tenant）+ 共享 Runtime（Shared Runtime）+ 模块化单体（Modular Monolith）。管理 API 与 Worker 作为不同进程部署，但共享领域代码和应用服务接口。
业务系统 / Web 控制台 / SDK→API Gateway / FastAPI→12 个业务功能模块→Agent Runtime / Worker
PostgreSQLRedisRabbitMQMilvusMinIOLLM Provider

2.1 模块分层

层次模块职责
资产配置层Agent、模型、Prompt、Tool、知识接入（MCP）、编排、记忆定义可复用能力和 Agent 版本配置。
执行层Runtime、任务管理将已发布配置装载为执行实例，调度、执行、恢复和返回结果。
质量运营层评估、可观测性度量质量、定位问题、追踪成本与性能。
横向治理层安全与权限贯穿所有模块，负责身份、租户、授权、审计、配额和风险控制。

2.2 关键模块依赖

  • Agent 管理中心引用模型、Prompt、Tool、Workflow、Knowledge、Memory 等指定版本。
  • Agent 编排中心定义 Workflow / Multi-Agent 结构，运行时由 Runtime 装载执行。
  • Runtime 负责执行，不承担 Agent 资产的编辑和发布管理。
  • 任务管理中心负责任务生命周期与 Worker 调度，不直接实现 LangGraph 图执行逻辑。
  • 安全与权限中心为所有资源读取、发布、调用和管理操作提供授权判断。
  • 评估中心和可观测性中心消费执行轨迹、事件和调用记录，但不改变业务执行结果。

3. 设计原则与全局约束

原则要求
租户隔离租户业务数据必须带 tenant_id；租户身份来自认证上下文，不信任请求体传入值。
版本不可变已发布的 AgentVersion 及其依赖配置快照不可原地修改；变更产生新版本。
发布与执行解耦开发态配置不直接被线上执行；执行必须绑定明确的 Release / Version。
资源引用可追溯Agent 版本引用具体模型、Prompt、工具、知识库和工作流版本，而非只保存逻辑资源 ID。
执行上下文独立共享 Runtime 中每次执行拥有独立 tenant、user、session、task、trace 和权限上下文。
异步可靠任务投递采用 Outbox 等可靠投递机制；消息至少一次，消费者必须幂等。
最小权限资源可见、资源可用、资源可编辑和资源可管理分开授权。
可审计发布、授权、密钥变更、工具调用、人工审批等关键行为记录审计事件。

3.1 全局数据约定

  • 关系型数据以 PostgreSQL 为主；动态配置可使用 JSONB，但核心关系仍使用明确字段和外键。
  • 时间统一使用 TIMESTAMPTZ，数据库 UTC 存储。
  • 主键统一采用 BIGINT 或 UUID，项目内保持一致。
  • 敏感密钥只保存密钥管理服务引用或加密后的密文，不以明文存储。
  • 缓存、向量数据和对象存储中的资源必须能追溯 tenant_id 与业务资源 ID。

4. 十二大功能模块需求

以下每个模块按“建设目标—功能需求—核心数据—业务流程—验收标准—边界”描述。功能优先级：P0 为首期必须具备，P1 为重要增强，P2 为后续完善。

01

Agent 管理中心

管理 Agent 的逻辑身份、配置版本、环境发布和调用入口。

建设目标

为开发者提供 Agent 生命周期管理能力，使 Agent 从创建、配置、测试到发布、回滚均可追溯，线上执行绑定明确发布版本。

功能需求

功能需求说明优先级
Agent 创建与基础信息创建 Agent，维护编码、名称、描述、类型、标签、归属租户、负责人和状态。P0
配置资源绑定绑定模型、Prompt、工具、Workflow、知识库和记忆策略；可设置资源角色与参数覆盖。P0
版本管理保存不可变配置快照、版本号、变更说明、创建人和配置 Hash。P0
环境发布支持 DEV/TEST/PROD 环境发布，记录发布人、发布时间、目标版本和发布状态。P0
回滚将环境当前发布指针切换到历史有效 Release，不覆盖历史记录。P0
调用配置配置同步/异步调用方式、超时、并发、输入输出 Schema 和调用授权。P1
版本差异对比对比两个版本的资源绑定、Prompt、模型参数和运行策略差异。P1

核心数据对象

Agent、AgentVersion、AgentRelease、AgentReleasePointer、AgentVersionResourceBinding。

核心流程

创建 Agent→配置能力资源→生成版本快照→测试→发布环境→线上调用

关键规则

  • Agent 是逻辑身份；Version 是不可变配置快照；Release 是版本在环境中的发布记录，三者不可混为一张表。
  • 发布指针切换不影响已创建任务；任务必须记录实际使用的 release_id 和 version_id。
  • 资源版本不可用或权限被撤销时，发布或执行前必须失败关闭并给出明确原因。

验收标准

  • 可以创建 Agent 并绑定至少一种模型、Prompt 和工具。
  • 修改配置后可生成新版本，旧版本内容保持不变。
  • 同一版本可发布到不同环境；环境发布指针可独立切换。
  • 历史任务可以准确追溯其 Agent Release 和依赖资源版本。

模块边界

只负责定义、版本、发布和调用配置；不负责执行 LangGraph，不负责实现模型调用或工具实际运行。

02

模型管理中心

统一接入模型供应商，管理模型能力、路由策略和调用成本。

建设目标

屏蔽不同模型供应商的 API 差异，提供统一模型注册、调用适配、路由、限流、降级和用量统计能力。

功能需求

功能需求说明优先级
供应商管理配置 OpenAI 兼容接口及其他供应商的 Base URL、认证凭据引用、区域和可用状态。P0
模型注册维护模型名称、供应商、模型标识、上下文窗口、输入输出模态、能力标签和状态。P0
模型参数模板配置 temperature、top_p、max_tokens、timeout 等参数及合法范围。P0
模型路由支持按租户、业务、模型能力、优先级或成本选择模型。P1
故障降级对超时、限流、供应商故障配置重试、备用模型和熔断策略。P1
限流与配额支持并发、RPM、TPM、租户级调用额度和供应商级保护。P0
用量与成本记录模型输入输出 Token、请求耗时、模型版本、计费单价和估算成本。P0
连通性测试管理员可测试凭据和模型连通性，结果不得泄露密钥。P0

核心数据对象

ModelProvider、Model、ModelVersion/Capability、ModelCredentialRef、ModelRoutePolicy、ModelUsage。

关键规则

  • 模型逻辑标识与供应商实际 model name 分开保存。
  • 密钥通过 Secret Manager 或加密凭据引用管理，不返回给前端。
  • 重试只针对可恢复错误；不得对非幂等工具副作用套用模型重试逻辑。
  • 记录实际供应商、模型标识和可获得的模型快照信息，承认供应商底层模型可能变化。

验收标准

  • 可接入至少两种模型配置或两个兼容端点。
  • Runtime 通过统一接口调用模型，不依赖具体供应商 SDK 细节。
  • 限流、超时、熔断和降级策略可配置且有日志。
  • 每次模型调用能关联租户、Agent、Task、Run 和 Trace。

模块边界

负责模型资源与调用策略；模型调用的具体执行由 Runtime 的 Model Adapter 完成。

03

Prompt 管理中心

管理提示词模板、变量、版本、测试和发布。

功能需求

功能需求说明优先级
模板管理支持 system/developer/user 等消息角色及多消息模板。P0
变量定义声明变量名称、类型、是否必填、默认值、描述和校验规则。P0
模板渲染测试输入测试变量，预览最终消息序列，检查缺失变量和非法变量。P0
版本管理保存版本快照、变更说明、作者和发布时间。P0
发布与回滚将 Prompt 版本发布到指定环境，支持切回历史版本。P0
测试样例维护输入样例、预期行为和人工备注，供评估中心调用。P1
敏感信息检查识别疑似密钥、个人信息或越权指令，提供风险提示。P1

核心数据对象

Prompt、PromptVersion、PromptVariable、PromptTestCase、PromptRelease。

关键规则

  • Prompt 版本发布后不可原地修改。
  • 变量必须有明确 Schema；渲染时对缺失变量和类型错误进行校验。
  • 模板中不得直接保存运行时密钥或用户敏感数据。
  • Agent Version 应绑定具体 PromptVersion。

验收标准

  • 可创建模板、定义变量并成功渲染预览。
  • 缺失必填变量时返回可定位的校验错误。
  • 可比较 Prompt 版本并追溯线上执行使用的版本。

模块边界

管理模板资产和版本；上下文拼装、变量注入和模型消息提交由 Runtime 执行。

04

Tool 工具管理中心

统一注册 Agent 可调用的内部 API、业务服务和外部工具。

功能需求

功能需求说明优先级
工具注册支持 HTTP API、Python 函数、MCP Server 等接入类型，维护名称、描述、归属和状态。P0
输入输出 Schema定义 JSON Schema，支持参数类型、必填、枚举、范围和输出结构。P0
工具版本工具定义、Schema、执行适配配置变更后形成新版本。P0
认证配置支持 API Key、OAuth、服务身份等凭据引用，密钥加密保存。P0
授权管理支持平台工具授权给租户，并控制租户内角色/用户使用范围。P0
调用策略配置超时、重试、并发、速率限制、熔断和幂等策略。P0
风险分级标记只读、写操作、高风险操作；高风险工具支持人工审批策略。P1
调用记录记录调用者、参数摘要、耗时、结果状态和错误信息，敏感字段脱敏。P0

核心数据对象

Tool、ToolVersion、ToolSchema、ToolCredentialRef、ToolPolicy、ToolCallRecord。

关键规则

  • 工具描述应明确用途、适用场景、输入输出和限制，减少模型误选工具。
  • 工具执行前由服务端再次做租户、用户和资源授权检查，不能只依赖模型是否发起调用。
  • 写操作应支持幂等键或业务侧去重；结果不确定时先对账，不能盲目重试。
  • 工具参数和返回值按敏感级别脱敏后进入日志。

验收标准

  • 可注册工具、配置 Schema、测试调用并绑定到 Agent。
  • 非法参数在执行前被拦截。
  • 未授权租户无法调用工具；高风险工具可触发审批。
  • 调用记录可按租户、工具、Agent、Task 查询。

模块边界

管理工具定义、版本和策略；实际调用由 Runtime Tool Executor 执行。

05

Agent 编排中心

通过可视化或配置化方式定义 Workflow 与 Multi-Agent 协作流程。

功能需求

功能需求说明优先级
流程画布提供节点、连线、分支、循环和子流程配置能力。P1
节点类型支持 LLM、Tool、条件判断、代码处理、人工审批、Agent 调用、检索等节点。P0
状态与变量定义输入输出、节点状态、变量映射和上下文传递规则。P0
条件路由支持基于结构化结果、表达式或模型分类结果的分支。P0
Multi-Agent支持 Supervisor/Worker 或显式任务委派模式，定义 Agent 职责和交接协议。P1
调试运行支持测试输入、单步执行、节点输入输出查看和失败定位。P0
版本与发布工作流配置版本化，发布后由 Runtime 按固定版本加载。P0
执行约束配置最大循环次数、最大节点数、总超时、并发和预算上限。P0

核心数据对象

Workflow、WorkflowVersion、WorkflowNode、WorkflowEdge、WorkflowRelease。

关键规则

  • 画布配置最终转换为可校验、可版本化的 Workflow Definition。
  • 发布前进行节点引用、输入输出 Schema、环路和权限校验。
  • LangGraph 是执行实现之一，编排领域模型不应与某个框架的内部对象强耦合。
  • 必须有最大步数、循环限制和总预算，避免 Agent 无限执行。

验收标准

  • 可创建至少包含 LLM、Tool、条件分支的流程。
  • 可校验流程连通性和必需输入。
  • 调试视图可查看节点状态、输入输出和错误。
  • 发布后的工作流版本可被 Agent Version 固定引用。

模块边界

负责编排定义、验证、版本和发布；Runtime 负责把定义转换为执行图并运行。

06

知识接入（MCP 外挂集成）

知识库不自建：通过 MCP 工具接入企业知识中台，平台只负责注册、鉴权、执行治理与可追溯。

范围决策（2026-11-23）：知识库不自建，知识检索能力通过 MCP 工具接入企业知识中台；本模块是集成，不是建设。

功能需求

功能需求说明优先级
MCP 工具注册按 MCP 传输（streamable_http / sse）注册知识中台端点与远端工具名，维护名称、描述、归属和状态。P0
调用契约登记 transport、url、远端 tool_name、输入/输出 JSON Schema 与超时；不声明本地进程，拒绝 stdio。P0
凭据引用通过密钥引用注入 Bearer 或自定义请求头，密钥加密保存且不在轨迹中回显。P0
授权管理MCP 工具按租户授权，未授权租户调用被拒绝；高风险知识操作可要求人工审批。P0
结果归一与校验远端文本/结构化结果归一为可校验值，按 output_schema 校验后再交给模型。P0
调用可追溯轨迹记录工具版本、远端 tool_name、耗时、状态和错误码，支持按租户、Agent、Run 查询。P0
知识质量抽查复用评估中心对召回质量做抽样评估，本模块不重复建设评估能力。P1

核心数据对象

Tool、ToolVersion（type=MCP）、ToolGrant、Secret、ToolCallRecord。

关键规则

  • 文档接入、解析、切分、Embedding、索引与检索生命周期由知识中台承担，平台不重复建设。
  • 只支持远程 HTTP 类 MCP 传输；平台不托管远端进程。
  • 工具执行前由服务端按租户、授权与风险等级再次校验，不能只依赖模型是否发起调用。
  • 远端失败只返回稳定错误码与截断后的错误摘要，不透传原始响应；写操作不自动重试。
  • 检索权限过滤由知识中台在服务端完成，平台不转发前端传入的过滤条件。

验收标准

  • 可注册知识中台的 MCP 工具并授权给目标租户。
  • Agent 版本绑定该工具并发布后，同步调用可返回知识中台的检索结果。
  • 同一 Run 的轨迹中同时出现模型调用与 MCP 工具调用，并记录远端工具名、耗时与状态。
  • 未授权租户调用被拒绝；远端失败返回可识别的错误码且不泄露原始响应。

模块边界

平台负责知识能力的接入、鉴权、执行治理与可追溯；知识生产、索引与检索质量由知识中台负责。

07

记忆管理中心

管理会话上下文、短期记忆、长期记忆和任务状态记忆。

功能需求

功能需求说明优先级
会话管理创建会话、归属用户和租户、维护标题、状态和最后活动时间。P0
消息历史保存用户消息、Agent 回复及必要的执行摘要，支持分页查询。P0
短期记忆维护当前 Run/Conversation 的上下文窗口和摘要。P0
长期记忆提取用户偏好、稳定事实或业务上下文，支持来源、置信度和有效期。P1
任务记忆保存任务执行中需要跨步骤共享的状态和中间结果引用。P0
记忆检索按用户、租户、会话、主题和语义相关度检索可用记忆。P1
记忆治理支持查看、修正、过期、删除和禁止使用特定记忆。P1
压缩策略按 Token 预算、消息重要性和任务边界触发摘要压缩。P1

核心数据对象

Conversation、Message、Memory、MemoryRecord、MemoryPolicy、ConversationSummary。

关键规则

  • 原始消息历史与提炼后的长期记忆分开保存，不能用摘要替代原始记录。
  • 记忆必须有 scope、source、created_at、expires_at、confidence 和访问控制。
  • 不同用户、租户的记忆严格隔离；共享业务记忆必须有显式授权。
  • 记忆写入和召回都应受策略控制，避免把所有历史消息无差别注入 Prompt。

验收标准

  • 可创建会话并持久化消息。
  • 同一会话后续执行可按策略读取历史上下文。
  • 可生成摘要并保留原始消息。
  • 记忆支持过期和删除，且检索遵循租户与用户权限。

模块边界

负责记忆数据和策略；Runtime 决定当前执行何时读取、写入和压缩记忆。

08

Agent Runtime 运行时中心

将已发布 Agent 配置装载为受控执行实例，是平台统一执行内核。

功能需求

功能需求说明优先级
配置解析与装载根据 Agent Release 获取不可变配置快照及依赖资源版本。P0
执行上下文构建构建 tenant、user、agent、release、task、run、session、trace 和权限上下文。P0
图执行引擎将 Agent/Workflow 配置转换为 LangGraph 等可执行图。P0
模型调用通过统一 Model Adapter 调用模型，处理超时、限流和可恢复错误。P0
工具调用通过 Tool Executor 校验参数、权限、预算和幂等策略后执行工具。P0
知识与记忆访问按 Agent 配置和当前用户权限调用检索、会话和记忆服务。P0
状态持久化集成 LangGraph Checkpointer，保存 checkpoint 引用和执行状态。P0
超时与预算支持总执行时限、最大步骤、最大工具调用数、Token 和成本预算。P0
暂停与恢复支持人工审批暂停、从 checkpoint 恢复和可控取消。P1
流式输出向调用方输出 token、节点状态或业务事件，需定义事件协议。P1

核心数据对象

ExecutionContext、RuntimeConfig、GraphInstance、CheckpointRef、ExecutionEvent。

关键规则

  • Runtime 是执行能力，Worker 是承载 Runtime 的进程；二者不能混为一谈。
  • 共享 Runtime 不代表共享状态；每次执行必须有独立上下文和隔离的 thread_id。
  • Runtime 不直接依赖具体数据库实现，通过 Repository/Service 接口访问配置、状态和资源。
  • 从 checkpoint 恢复前必须判断外部副作用是否已发生；不能对不确定的写操作盲目重放。

验收标准

  • 可按指定 Release 装载 Agent 并执行。
  • 模型、工具、检索和记忆调用均关联统一 Trace。
  • 执行达到超时或预算上限时能够按策略终止。
  • 多租户并发执行时上下文、权限和状态互不串扰。

模块边界

负责执行编排和运行控制；任务排队与 Worker 生命周期由任务管理模块负责。

09

任务管理中心

管理同步/异步调用形成的 Task、Run、队列、状态、重试和取消。

功能需求

功能需求说明优先级
任务创建接收调用请求，校验租户、Agent Release 和输入 Schema，创建 Task。P0
异步调度通过 RabbitMQ 投递任务，由 Worker 消费执行。P0
状态管理维护 WAITING、QUEUED、RUNNING、RETRY_WAITING、PAUSED、SUCCESS、FAILED、CANCELLED 等状态。P0
Run 管理一个 Task 可有多个 Run；重试通常创建新 Run，记录尝试次数和执行快照。P0
进度事件记录节点开始/结束、工具调用、等待审批、重试和最终结果等事件。P0
失败重试支持错误分类、最大重试次数、指数退避和死信处理。P0
Worker 租约记录 worker_id、heartbeat 和 lease_until，支持 Worker 崩溃后的任务回收。P0
取消与恢复支持用户取消、管理员终止、暂停后恢复及 checkpoint 恢复。P1
结果查询按 task_id 获取状态、结果、错误摘要和事件列表。P0

核心数据对象

Task、Run、CheckpointRef、ExecutionEvent、TaskResult、OutboxEvent。

核心流程

创建 Task→写入 Outbox→RabbitMQ→Worker 领取→创建/更新 Run→Runtime 执行→保存结果与事件

关键规则

  • Task 表示业务任务；Run 表示一次执行尝试；Checkpoint 表示图状态快照；Event 表示追加式过程事件。
  • 数据库写任务与 MQ 投递应使用 Outbox 或等效可靠机制，避免双写不一致。
  • 消息按至少一次投递设计，Worker 消费必须幂等。
  • 重试前区分可恢复错误、业务错误、权限错误和副作用不确定错误。
  • 取消是协作式控制：Worker/Runtime 必须定期检查取消信号。

验收标准

  • 异步任务创建后能返回 task_id，调用方可查询状态和结果。
  • Worker 崩溃后，过期租约任务可被回收。
  • 重复消息不会造成重复业务执行。
  • 任务状态流转合法，失败、取消、重试均有事件记录。

模块边界

负责任务生命周期、调度和状态；不实现 Agent 推理逻辑，不实现 LangGraph 图本身。

功能需求说明优先级

RBAC 权限平台角色、租户角色、权限点、用户角色分配和部门范围控制。P0
资源授权平台模型、Prompt、Tool、Workflow、Knowledge 等资源授权给租户或指定主体。P0

核心数据对象

Tenant、Department、User、UserTenant、Role、Permission、RolePermission、UserRole、ResourceGrant、APIKey、AuditLog、Quota。

关键规则

  • 租户身份必须来自可信认证上下文，不能信任客户端自行传入的 tenant_id。
  • RBAC 判断“能否执行某类操作”；Resource Grant 判断“能否访问某个具体资源”。二者需要组合判断。
  • PostgreSQL RLS 作为纵深防御，不能替代应用层权限校验；连接池必须避免租户上下文泄漏。
  • 平台管理员权限与租户角色授权路径隔离。
  • 配额检查应在任务入队和执行过程中分别考虑，防止排队与运行阶段突破预算。

验收标准

  • 用户不能跨租户读取或修改无权访问的数据。
  • 禁用租户、用户、API Key 后，后续请求被拒绝。
  • 资源授权撤销后，新的资源访问立即或在明确的缓存失效时限内被阻断。
  • 关键管理操作可查询审计记录。

模块边界

作为横向治理模块，为其他模块提供身份、权限、密钥和配额服务；不拥有 Agent、Tool、Knowledge 等业务资源的具体配置内容。

5. 端到端业务流程

5.1 Agent 创建、测试与发布

开发者创建 Agent→绑定模型/Prompt/Tool/知识库→配置 Workflow→生成 Version→调试与评估→发布 Release→切换环境指针
  1. 安全与权限中心校验用户是否有 Agent 创建和资源使用权限。
  2. Agent 管理中心保存逻辑 Agent 和资源绑定。
  3. Prompt、模型、工具、Workflow 和 Knowledge 资源均引用确定版本。
  4. 评估中心可对候选版本执行离线评估。
  5. 发布时创建 Release，更新对应环境的发布指针。
  6. 线上调用解析发布指针并固定 Release，运行中不因指针变化而改变配置。

5.2 同步调用 Agent

业务系统请求→认证/租户/权限→解析 Release→Runtime 执行→返回结果

适用于短耗时、可在 HTTP 请求生命周期内完成的交互。应设置请求超时和执行预算；超过阈值应引导使用异步任务接口。

5.3 异步调用 Agent

创建 Task→Outbox→RabbitMQ→Worker→Runtime→Task 结果/事件

创建成功后立即返回 task_id。调用方通过 Task API 轮询，或通过 SSE/WebSocket 订阅事件。Worker 负责领取任务、心跳续租、执行、提交状态和释放资源。

5.4 知识库构建

上传/接入文档→创建 Ingestion Job→解析与清洗→Chunk→Embedding/抽取→索引构建→验证与发布

处理任务应可观测、可重试、可恢复。文档元数据与任务状态存 PostgreSQL，原始文件和中间产物存 MinIO，向量索引存 Milvus；GraphRAG 图数据按选型存储并保留实体关系来源。

5.5 人工审批与恢复

  1. Runtime 执行到需要审批的节点，生成审批请求并暂停当前执行。
  2. 审批记录关联 tenant_id、task_id、run_id、节点和待审批动作摘要。
  3. 审批人通过权限校验后批准或拒绝。
  4. 批准后恢复执行；拒绝后按工作流配置终止或走补偿分支。
  5. 审批过程完整记录审计事件。

6. 核心数据对象与存储职责

存储主要数据使用原则
PostgreSQL租户、用户、权限、Agent、版本、发布、任务、Run、会话消息元数据、评估结果、审计记录业务事实来源；使用事务、外键、唯一约束和 tenant_id 隔离。
Redis缓存、限流计数、短期状态、分布式锁/租约辅助、事件游标缓存不作为唯一事实来源；设置 TTL 和失效策略。
RabbitMQ异步任务、重试消息、事件通知至少一次投递；消费端幂等；失败消息进入死信或人工处理流程。
Milvus文档 Chunk 向量及向量索引必须通过租户/知识库/权限过滤保证检索隔离。
MinIO原始文档、图片、解析产物、导出文件对象 Key 不可作为授权机制；下载必须经过服务端鉴权。
Checkpoint StoreLangGraph 执行状态快照业务库保存 checkpoint 引用；状态快照需有保留和清理策略。
Telemetry BackendTrace、Span、日志、指标支持采样、脱敏、保留周期和成本控制。

6.1 关键关系约束

  • Task 固定关联 agent_id、agent_release_id、agent_version_id、tenant_id。
  • Run 关联 Task，记录 worker_id、thread_id、执行配置快照和尝试序号。
  • CheckpointRef 关联 Run，不把 LangGraph 内部快照结构复制成业务领域表。
  • ExecutionEvent 追加写入，保存业务进度，不覆盖历史事件。
  • AgentVersionResourceBinding 绑定资源的具体版本。

8.1 初始 SLO 建议（需压测后确认）

  • 管理类 API：目标 P95 小于 500ms，不含外部依赖调用。
  • 异步任务创建：目标 P95 小于 300ms，成功返回 task_id 即表示已受理，不代表执行完成。
  • 任务状态更新：关键状态持久化后再对外确认。
  • 平台可用性、任务完成时限和恢复时间需结合部署规模及业务 SLA 另行确认。

9. 分期建设建议

第一期：平台最小闭环

  • 安全与权限：租户、成员、RBAC、资源授权、基础审计。
  • 模型管理：模型接入、参数、凭据引用、基础限流。
  • Prompt 管理：模板、变量、版本。
  • Tool 管理：注册、Schema、授权、调用。
  • Agent 管理：创建、绑定、版本、发布。
  • Runtime：配置装载、LangGraph 执行、模型和工具调用。
  • 任务管理：异步任务、Worker、状态、结果、重试基础能力。
  • 可观测性：Trace、错误、耗时和 Token 基础记录。

第二期：知识与复杂编排

  • 知识接入：通过 MCP 接入企业知识中台，平台不建设解析、切分、Embedding 与索引。
  • 编排中心：可视化 Workflow、条件分支、Multi-Agent、调试和发布。
  • 记忆中心：会话消息、摘要、短期记忆和长期记忆策略。
  • 任务管理增强：取消、暂停、恢复、审批节点、死信处理。

第三期：质量治理与平台化运营

  • 评估中心：数据集、离线评估、版本对比、人工评审。
  • 可观测性增强：检索轨迹、告警、成本分析和运营报表。
  • 治理增强：细粒度配额、风险分级、敏感信息治理和审批策略。
  • GraphRAG、更多数据源连接器和高级路由策略按业务价值逐步接入。
实施提醒：12 个模块是产品能力边界，不代表首期必须建设 12 个独立微服务。建议先以模块化单体组织管理服务，Runtime Worker 独立进程运行，待出现明确的团队边界或扩展瓶颈后再拆分服务。

10. 全局验收标准

  1. 平台管理员可以创建租户并为租户配置成员、角色和配额。
  2. 租户开发者可以创建 Agent，绑定模型、Prompt、Tool 和知识库资源。
  3. Agent 可以生成不可变版本，发布到指定环境并支持回滚。
  4. 业务系统可以通过 API 同步调用或创建异步任务。
  5. 异步任务由 Worker 执行，支持状态查询、进度事件、失败记录和可控重试。
  6. Runtime 能够追踪一次执行中的模型调用、工具调用、检索和工作流节点。
  7. 知识库可以完成文档接入、解析、索引构建、检索和增量更新。
  8. 会话历史可持久化，记忆按用户和租户权限隔离。
  9. 评估中心可以运行数据集并对比不同 Agent/Prompt 版本。
  10. 跨租户越权访问、未授权工具调用和失效 API Key 均被阻断。
  11. 关键管理、发布、授权和高风险操作均有审计记录。
  12. 平台能提供基础成功率、失败率、延迟、Token、成本和队列积压指标。

11. 范围边界与待决策项

11.1 当前不默认纳入首期的内容

  • 自研基础大模型训练和 GPU 资源调度平台。
  • 替代企业现有 IAM/SSO 身份源。
  • 替代业务系统自身的订单、客户、法律案件等业务数据管理。
  • 自建知识库（文档解析、切分、Embedding、向量/图索引）：知识能力通过 MCP 接入知识中台，属于集成而非建设。
  • 所有外部工具协议和数据源连接器一次性全量支持。
  • 一开始将 12 个模块全部拆成独立微服务。

11.3 需求变更原则

新增需求应明确所属模块、数据归属、租户隔离方式、权限点、API/事件契约、运行时影响和验收标准。跨模块需求由模块负责人共同评审，避免一个模块直接侵入另一个模块的领域数据。

文档结论

本需求文档定义了企业级 Agent 中台的 12 个核心功能模块及其职责边界。平台以 Agent 资产管理为中心，以统一 Runtime 为执行核心，以任务管理承载异步执行，以安全权限作为横向治理基础，并通过评估与可观测性形成质量闭环。

推荐落地顺序：先完成租户权限、模型、Prompt、Tool、Agent、Runtime、任务管理的最小闭环，再逐步建设知识库、编排、记忆、评估和高级治理能力。
