# 运行时上下文：把平台事实交给模型，而不是让它猜

模型不知道「现在几点」「今天是哪天」这类运行时事实。让调用方在输入里塞一个日期很危险：
谁都能伪造，而且每个调用方都得记得塞。

平台采用**声明式依赖**：版本声明自己需要哪些事实，平台在执行时注入。

## 声明方式

```json
{
  "runtime_context": ["now", "timezone"]
}
```

目前支持的事实项：

| 项 | 渲染内容 |
| --- | --- |
| `now` | `当前时间：2026-11-24T09:30:05+08:00（周二）` |
| `timezone` | `时区：Asia/Shanghai` |

未声明不注入；声明未知项在保存版本时直接报错，并在错误详情里指出是哪一项。

## 生效范围

- 位置：插在 system 消息之后、历史消息之前。
- 不进入 `messages` 状态，也不写入检查点历史：下一轮不会累积出第二条上下文。
- 一次 run 只取一次：工具循环里多轮调用看到的时刻相同，不会因为跨过整点而前后不一致。
- 调用方输入无法覆盖：即使 `input` 里出现同名键，也只会进入模板变量，不改变上下文消息。
- 与 Prompt 占位符的区别：占位符由调用方提供值，属于业务输入；运行时上下文由平台提供值，
  属于环境事实，因此不进快照值、不接受覆盖。

## 在控制台声明

Agent 详情页的配置表单里有「运行时上下文」多选，覆盖 `now` / `timezone`：

1. 勾选后会写进 `POST /agents/{id}/versions` 的 `runtime_context`；未勾选即不注入。
2. 以某版本为基础编辑时，勾选状态按该版本快照回显；清空全部会先确认，
   因为清空后模型只能依据用户输入推断相对时间。
3. 保存成功后会比对响应快照里的声明：旧后端会静默忽略未知字段，
   这种情况会提示「声明未生效」，而不是等到下一轮执行才暴露。
4. 版本对比页的「运行时上下文」一节展示基线与目标各自的声明项，并标注已变更/未变更。

调试台与配置页预览也会带上声明（预览请求的 `runtime_context` 字段），
因此不必先保存版本就能验证效果。预览面板显示本轮实际注入的项（取 `preview_snapshot.runtime_context`），
尚未执行时退回显示版本声明并标注来源。

预览会话沿用首轮装配的快照，所以同一会话内切换声明不会改变已建立会话的注入行为。

## 快照与版本对比

快照只记录「需要哪些事实」：

```json
{"runtime_context": ["now", "timezone"]}
```

它参与 `config_hash` 计算，也出现在版本对比结果里：

```json
{
  "identical": false,
  "config_hash_changed": true,
  "runtime_context": {"changed": true, "base": [], "target": ["now", "timezone"]}
}
```

事实值本身（具体时间、时区名）不写入快照，避免同一版本在不同时间产生不同指纹。

## 新增事实项

1. 在 `agent/domain/snapshot.py` 的 `RUNTIME_CONTEXT_ITEMS` 里登记名称。
2. 在 `execution/runtime/context.py` 的渲染逻辑里补一行。
3. 补一条单测：固定时钟断言渲染文本，以及「未声明不出现」。
4. 在本文档的事实项表格里登记。
