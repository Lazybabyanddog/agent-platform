# Spec Delta

## MODIFIED Requirements

### Requirement: 运行指标可查询

系统 SHALL 支持按租户、Agent、环境与会话聚合查询调用量、成功率、失败率、耗时分布与会话数。调用量与会话数 SHALL 分别统计，同一会话的多次调用计入多次调用但只计入一个会话。聚合 MUST 默认排除预览运行；系统 SHALL 支持显式包含预览运行，以便分析调试行为。

#### Scenario: 按 Agent 查看成功率

- **WHEN** 运维人员查询某 Agent 在时间范围内的运行情况
- **THEN** 系统返回调用量、成功与失败数量以及延迟分位值

#### Scenario: 定位最慢步骤

- **WHEN** 运维人员查看某次失败的运行
- **THEN** 系统返回各步骤耗时，可识别最耗时或失败的步骤

#### Scenario: 按会话统计

- **WHEN** 同一会话在统计区间内发生了五次调用
- **THEN** 调用量计入五次，会话数计入一个

#### Scenario: 默认排除预览

- **WHEN** 运维人员查看某 Agent 的正式调用指标，而该时间段内存在调试预览
- **THEN** 预览运行不计入调用量、成功率与耗时分布

#### Scenario: 显式包含预览

- **WHEN** 运维人员显式选择包含预览运行
- **THEN** 结果包含预览运行，并可按运行种类区分

## ADDED Requirements

### Requirement: 运行种类可区分

每条运行记录 SHALL 带有运行种类，至少区分正式调用与预览执行。查询与导出 SHALL 支持按运行种类筛选。预览运行 SHALL 记录其配置摘要，正式运行 SHALL 记录发布记录与版本标识，使两类运行都可被解释。

#### Scenario: 按种类筛选运行

- **WHEN** 用户筛选运行种类为预览
- **THEN** 结果只包含预览执行，且每条可查看其配置摘要

#### Scenario: 正式运行可追溯版本

- **WHEN** 用户查看一条正式运行
- **THEN** 可定位到它使用的发布记录与版本
