# Spec Delta

## ADDED Requirements

### Requirement: 追踪正文的落库与查看

系统 SHALL 在追踪记录中保留模型调用的完整请求消息与完整响应正文，作为排障与复盘的事实来源；工具调用的敏感字段 MUST 仍按参数 schema 脱敏后落库，凭据原文 MUST NOT 进入普通日志。

#### Scenario: 调用正文随追踪落库

- **WHEN** 一次模型调用结束（成功或因限流、超时、供应商错误失败）
- **THEN** 追踪记录包含该次调用的完整请求消息与响应正文，不需要任何租户级开关预先开启

#### Scenario: 敏感工具参数仍脱敏

- **WHEN** 工具参数中包含被标记为敏感的字段
- **THEN** 落库与查询结果中该字段仍以掩码呈现，与模型调用正文的保留策略无关

#### Scenario: 无权限者只见摘要

- **WHEN** 调用方不具备正文查看权限
- **THEN** 追踪接口只返回内容摘要与长度，不返回完整正文与完整响应

## REMOVED Requirements

### Requirement: 敏感内容不进入普通日志

**Reason**: 该要求以租户级开关作为正文落库与展示的闸门，默认关闭导致追踪记录不含任何正文，排障只能看摘要；同时它被复用为会话回放的展示开关，而会话正文本就存在于会话上下文中，开关没有保护数据，只损失了可用性。

**Migration**: 由「追踪正文的落库与查看」取代。模型调用与工具调用的正文随追踪恒定落库，敏感字段仍按参数 schema 脱敏；查看完整正文改为只由调用方权限决定，不再有租户级开关。
