# Spec Delta

## Purpose

让具备工具读写权限的租户成员在浏览器里完成工具的注册、契约维护、版本迭代、授权与启停，并能当场验证一次真实调用；工具对 Agent 是否可用（已启用、已授权）在界面上一眼可见，不再依赖命令行或猜测错误码。

## ADDED Requirements

### Requirement: 工具管理入口与列表

控制台 SHALL 为具备 `TOOL_READ` 的用户提供「工具管理」入口。列表 SHALL 展示每个工具的 `code`、名称、类型、风险等级、启用状态与授权状态，并支持按 `code` 或名称进行本地过滤，不逐次请求服务端。列表为空时 SHALL 展示空状态与新建引导；加载失败时 SHALL 展示错误与重试，而不是空白页面。

#### Scenario: 进入列表

- **WHEN** 具备 `TOOL_READ` 的用户打开工具管理
- **THEN** 系统展示本租户全部工具的 code、名称、类型、风险等级、启用状态与授权状态

#### Scenario: 按关键字过滤

- **WHEN** 用户在搜索框输入 code 或名称片段
- **THEN** 列表即时收敛为匹配项，清空输入后恢复全部

#### Scenario: 无数据

- **WHEN** 本租户还没有任何工具
- **THEN** 列表展示空状态与新建入口，不显示报错

#### Scenario: 风险与状态可识别

- **WHEN** 列表中同时存在只读、写操作与高风险工具，以及启用与停用的工具
- **THEN** 每行以不同视觉标识区分风险等级与启用状态，不需要进入详情才能分辨

### Requirement: 新建工具

新建 SHALL 采集 `code`、名称、描述、风险等级与工具定义。`code` SHALL 在前端按后端规则校验（1~64 位，仅字母、数字与 `_.-`）。创建成功后 SHALL 进入该工具的详情页继续做授权与验证。后端返回唯一性冲突时 SHALL 在 `code` 字段上提示，且不丢失已填内容。缺少 `TOOL_MANAGE` 的用户 SHALL NOT 看到新建入口，也不得通过直接访问地址提交写请求。

#### Scenario: 创建成功

- **WHEN** 用户填写合法 `code`、名称、描述、风险等级与工具定义并提交
- **THEN** 系统创建工具及其首个版本，并跳转到该工具详情页

#### Scenario: code 冲突

- **WHEN** 提交的 `code` 在本租户已存在
- **THEN** 界面在 `code` 字段提示冲突，其余输入保持不变

#### Scenario: 定义不合法

- **WHEN** 提交的定义缺少 URL 或方法不受支持
- **THEN** 界面把后端的字段级错误定位到对应输入项，且不创建工具

#### Scenario: 只读用户

- **WHEN** 用户没有 `TOOL_MANAGE` 权限
- **THEN** 新建入口不可见，直接访问新建地址也不会提交写请求

### Requirement: 工具定义编辑

工具定义编辑 SHALL 对 HTTP 类型工具提供结构化表单（请求方法、URL、超时、请求头、认证方式与凭据引用）以及 `input_schema`、`output_schema` 两个 JSON 文本域；对未识别的工具类型 SHALL 退化为完整定义的 JSON 编辑，以保证新增类型时控制台仍可用。JSON 文本域在提交前 SHALL 做语法校验并在原位置提示错误；结构与语义是否合法 SHALL 以后端返回为准，前端不重新实现 JSON Schema 校验规则。

#### Scenario: 结构化编辑 HTTP 工具

- **WHEN** 用户编辑一个 HTTP 工具的方法、URL、超时与请求头
- **THEN** 界面把这些输入组合成工具定义并提交，未填写的可选配置不出现在结果中

#### Scenario: JSON 语法错误

- **WHEN** 用户在入参或出参 Schema 中留下非法 JSON 就尝试保存
- **THEN** 保存被阻止，错误提示定位到该文本域，其他字段保持可编辑

#### Scenario: 后端拒绝定义

- **WHEN** 后端返回定义校验失败（如 URL 非绝对地址、超时超过上限、Schema 顶层不是 object）
- **THEN** 界面按错误中的字段路径定位到对应输入项并保留用户已填内容

#### Scenario: 认证凭据引用

- **WHEN** 用户选择 bearer 或 header 认证
- **THEN** 界面要求绑定一个凭据引用；当用户缺少 `SECRET_MANAGE` 而无法列出凭据时，界面提示原因并允许手工填写凭据标识

#### Scenario: 未识别的工具类型

- **WHEN** 打开一个非 HTTP 类型工具的定义
- **THEN** 界面以完整 JSON 形式展示并编辑其定义，不显示不适用的表单字段

### Requirement: 版本新增与不可变

保存定义 SHALL 新增一个版本，而不是修改既有版本；版本列表 SHALL 展示版本号、风险等级、创建时间与配置指纹，且历史版本只读。相对最新版本没有任何变更时 SHALL 禁用保存，避免产生空版本。版本新增成功后 SHALL 以新版本作为当前展示版本。

#### Scenario: 修改定义

- **WHEN** 用户修改 URL 或 Schema 后保存
- **THEN** 系统创建版本号加一的版本，并把它作为当前版本展示

#### Scenario: 仅调整风险等级

- **WHEN** 用户只把风险等级从只读改为写操作并保存
- **THEN** 系统同样创建新版本，不原地修改旧版本

#### Scenario: 无变更保存

- **WHEN** 当前编辑内容与最新版本一致
- **THEN** 保存操作不可用，不会产生新版本

#### Scenario: 只读用户查看历史

- **WHEN** 没有 `TOOL_MANAGE` 权限的用户打开版本列表
- **THEN** 可以查看全部版本及其定义，但没有编辑或新增版本入口

### Requirement: 授权与启停

详情页 SHALL 展示本租户对该工具的授权状态，并允许具备 `TOOL_MANAGE` 的用户授权或撤销授权；授权语义 SHALL 表述为"授权给本租户（授权后可用于 Agent 绑定）"，不提供选择其它租户的入口。具备 `TOOL_MANAGE` 的用户 SHALL 能切换工具的启用状态。工具处于停用或未授权状态时，详情页 SHALL 明确提示该工具当前不可被 Agent 绑定或调用。

#### Scenario: 授权本租户

- **WHEN** 用户对一个未授权工具点击授权
- **THEN** 授权状态变为已授权，并展示授权时间，测试调用与 Agent 绑定随即可用

#### Scenario: 重复授权

- **WHEN** 用户对一个已授权工具再次触发授权
- **THEN** 界面不发出重复请求，或按后端冲突结果提示"已授权"而不表现为失败

#### Scenario: 撤销授权

- **WHEN** 用户在确认后撤销授权
- **THEN** 授权状态变为未授权，界面提示该工具已不可被新的 Agent 版本绑定

#### Scenario: 停用工具

- **WHEN** 用户把一个启用中的工具切换为停用
- **THEN** 状态更新为停用，界面提示引用了该工具的 Agent 版本在运行时会调用失败

#### Scenario: 只读用户

- **WHEN** 用户只有 `TOOL_READ` 权限
- **THEN** 授权状态与启用状态可见，但授权、撤销与启停入口不可见

### Requirement: 测试调用

详情页 SHALL 提供测试调用：以当前选中版本为对象，接收一个 JSON 对象作为入参，展示调用状态、输出、耗时与请求/响应指纹。风险等级为高风险时 SHALL 要求用户显式确认后才发起请求。调用失败时 SHALL 展示后端返回的错误码，并把字段级原因定位到对应输入项或参数路径，而不是笼统提示失败。界面 SHALL 明示测试调用不会进入工具调用记录。

#### Scenario: 调用成功

- **WHEN** 用户填入符合入参 Schema 的参数并触发测试
- **THEN** 界面展示输出内容、耗时与指纹，并标明调用成功

#### Scenario: 入参不符合契约

- **WHEN** 参数缺少必填字段或类型不符
- **THEN** 界面展示参数校验错误与具体字段路径，不展示任何输出

#### Scenario: 高风险工具

- **WHEN** 用户对高风险工具触发测试但未确认风险提示
- **THEN** 请求不发出；确认后才携带高风险放行标记发起请求

#### Scenario: 未授权或已停用

- **WHEN** 用户对未授权或已停用的工具触发测试
- **THEN** 界面在发起前即提示不可调用并指向授权或启用操作，而不是只抛出一个错误码

#### Scenario: 上游失败或超时

- **WHEN** 上游返回非 2xx 或超过超时上限
- **THEN** 界面展示对应错误码与上游状态，保留入参以便重试

### Requirement: 调用概览

详情页 SHALL 展示该工具的调用概览：时间窗口内的调用量、成功率、平均耗时与最近若干条调用记录（时间、状态、耗时、错误码）。记录只包含摘要信息，不展示请求与响应正文。没有调用记录时 SHALL 展示空状态并说明工具尚未被 Agent 调用，而不是显示为零值统计。

#### Scenario: 有调用记录

- **WHEN** 工具在时间窗口内被调用过
- **THEN** 界面展示调用量、成功率、平均耗时以及按时间倒序的最近调用条目

#### Scenario: 无调用记录

- **WHEN** 工具从未被 Agent 调用（例如刚创建）
- **THEN** 界面展示空状态说明，不展示容易误解的 0% 成功率

#### Scenario: 失败集中于某个错误码

- **WHEN** 最近调用中存在失败且错误码可区分（超时、上游错误、输出不符合契约）
- **THEN** 每条记录展示各自错误码，用户可据此判断是配置问题还是上游问题

#### Scenario: 正文不可见

- **WHEN** 租户未开启正文留存
- **THEN** 调用条目仍展示状态与耗时，但不提供任何查看正文的入口

### Requirement: 只读降级

控制台 SHALL 以服务端返回的权限集合为唯一依据决定写操作可见性。只具备 `TOOL_READ` 的用户访问列表与详情 SHALL 能查看定义、版本、授权与启用状态、测试结果入口之外的只读信息，页面不因缺失权限而报错。任何写操作入口在无权限时 SHALL 隐藏而非禁用后仍可点击。

#### Scenario: 只读访问详情

- **WHEN** 只读用户直接打开某工具详情地址
- **THEN** 页面正常展示概览、定义与版本，编辑、授权、启停与测试入口不可见

#### Scenario: 权限缺失不报错

- **WHEN** 只读用户加载详情页
- **THEN** 页面不出现权限错误提示，也不发起任何写请求
