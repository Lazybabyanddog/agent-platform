# Spec Delta

## Purpose

集中管理第三方凭据的保存与取用方式，并对影响线上行为与权限边界的关键操作留下不可篡改的审计记录，使事后追责与事故复盘有据可依。

## ADDED Requirements

### Requirement: 凭据以引用方式保存

系统 SHALL 以引用或加密密文形式保存模型供应商与工具的认证凭据。任何接口的响应、日志、事件载荷中均不得出现凭据原文。

#### Scenario: 查询凭据

- **WHEN** 管理员查询已保存的凭据
- **THEN** 系统返回引用标识与掩码，不返回明文

#### Scenario: 执行失败时的错误信息

- **WHEN** 使用某凭据调用外部服务失败
- **THEN** 错误信息与执行记录中包含凭据引用标识与失败原因，不包含凭据原文

### Requirement: 凭据轮换与失效

系统 SHALL 支持替换凭据内容并保留引用标识不变，使引用该凭据的资源配置无需改动。被禁用的凭据在此后的调用中必须失败关闭。

#### Scenario: 轮换凭据

- **WHEN** 管理员更新某凭据的内容
- **THEN** 引用同一凭据的模型或工具在下一次调用时使用新内容，且无需重新配置

#### Scenario: 使用已禁用凭据

- **WHEN** 某模型引用的凭据已被禁用
- **THEN** 调用该模型时返回明确的凭据不可用错误，不发起外部请求

### Requirement: 关键操作审计

系统 SHALL 为 Agent 发布、环境指针变更、回滚、资源授权变更、API Key 创建与禁用、凭据变更、工具注册与版本生成记录审计事件。审计事件必须包含租户、操作者、操作类型、目标资源、结果与时间。

#### Scenario: 发布产生审计记录

- **WHEN** 某 Agent 版本被发布到某环境
- **THEN** 系统写入一条审计事件，包含发布者、租户、Agent、版本、环境与发布时刻

#### Scenario: 审计记录不可修改

- **WHEN** 任意接口尝试更新或删除已写入的审计事件
- **THEN** 系统拒绝该操作

#### Scenario: 失败的授权变更也留痕

- **WHEN** 一次资源授权变更因权限不足被拒绝
- **THEN** 系统仍写入一条结果为失败的审计事件

### Requirement: 审计记录查询与隔离

系统 SHALL 提供按租户、时间范围、操作类型与目标资源查询审计记录的接口，查询结果必须限制在调用者有权访问的租户范围内。

#### Scenario: 按目标资源追溯

- **WHEN** 审计人员按某 Agent 标识查询审计记录
- **THEN** 系统返回该 Agent 的发布、回滚与授权变更记录，按时间倒序排列

#### Scenario: 跨租户查询审计

- **WHEN** 某租户用户查询另一租户的审计记录
- **THEN** 系统返回空集或无权限结果
