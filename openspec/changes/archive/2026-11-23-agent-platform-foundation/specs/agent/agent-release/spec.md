# Spec Delta

## Purpose

把 Agent 的逻辑身份、不可变配置版本与环境发布拆成三层，使线上执行始终绑定一个确切的历史快照，从而支持审计、回滚与评估复现。

## ADDED Requirements

### Requirement: Agent 逻辑身份

系统 SHALL 维护 Agent 的逻辑身份，包含租户内唯一编码、名称、类型、负责人、标签与状态。逻辑身份本身不承载可执行配置。

#### Scenario: 创建 Agent

- **WHEN** 开发者在某租户下提交唯一编码与名称
- **THEN** 系统创建 Agent 并返回标识，其状态为草稿

#### Scenario: 编码冲突

- **WHEN** 同一租户下提交已存在的 Agent 编码
- **THEN** 系统拒绝创建并返回冲突错误

### Requirement: 版本生成即固化快照

生成 Agent 版本时，系统 SHALL 把模型、Prompt、工具的具体版本引用与参数覆盖固化进不可变快照，并计算配置摘要。快照生成后不随被引用资源的变化而变化。

#### Scenario: 生成版本快照

- **WHEN** 开发者为绑定了一个模型、一个 Prompt 与一个工具的 Agent 生成版本
- **THEN** 系统保存包含三者确切版本信息的快照与配置摘要

#### Scenario: 被引用资源变更不影响旧版本

- **WHEN** 关联的 Prompt 在之后生成新版本
- **THEN** 已生成的 Agent 版本快照内容与其配置摘要保持不变

#### Scenario: 同配置重复生成得到相同摘要

- **WHEN** 以完全相同的资源配置连续生成两个版本
- **THEN** 两个版本的配置摘要一致，版本号不同

### Requirement: 版本与资源绑定的可追溯关系

系统 SHALL 记录每个 Agent 版本对具体资源版本的绑定关系，包含资源类型与资源版本标识，以供授权校验与影响面分析查询。

#### Scenario: 查询版本依赖

- **WHEN** 审计人员查询某 Agent 版本的绑定关系
- **THEN** 系统返回其引用的模型、Prompt 与工具的确切版本标识

### Requirement: 环境发布与唯一发布指针

系统 SHALL 支持向 DEV、TEST、PROD 环境发布版本。每个 Agent 在每个环境最多存在一个当前发布指针，指向一条发布记录。发布记录一经创建不可修改。

#### Scenario: 发布到环境

- **WHEN** 开发者把某版本发布到 PROD
- **THEN** 系统创建发布记录并把该环境的发布指针指向它

#### Scenario: 指针唯一

- **WHEN** 同一 Agent 再次向同一环境发布
- **THEN** 系统创建新的发布记录并更新指针，历史发布记录保留

### Requirement: 回滚

系统 SHALL 支持把某环境的发布指针切回历史发布记录。回滚不得删除或修改任何历史发布记录。

#### Scenario: 回滚到上一发布

- **WHEN** 管理员把 PROD 指针切回上一发布记录
- **THEN** 后续调用使用该发布记录对应的版本，原发布记录仍可查询

#### Scenario: 进行中的调用不受影响

- **WHEN** 发布指针切换时有调用正在执行
- **THEN** 该次调用继续使用其开始时的发布与版本直至结束

### Requirement: 引用不可用时失败关闭

当 Agent 版本引用的资源版本被停用、被删除或不再对本租户授权时，发布与发布后的调用 MUST 失败关闭并给出具体原因。

#### Scenario: 引用资源被撤销授权

- **WHEN** 某 Agent 版本引用的工具对当前租户的授权被撤销后发起调用
- **THEN** 调用失败并返回被撤销授权的具体资源

#### Scenario: 发布引用已停用资源

- **WHEN** 尝试发布引用了已停用 Prompt 版本的 Agent 版本
- **THEN** 发布被拒绝并返回具体不可用原因

### Requirement: 发布事件通知

系统 SHALL 在发布成功时通过消息通道至少一次投递发布事件，事件包含租户、Agent、版本、环境与发布记录标识。重复投递不影响系统状态。

#### Scenario: 发布后产生事件

- **WHEN** 某版本成功发布到某环境
- **THEN** 系统向外投递一条可被订阅者识别为发布完成的业务事件

#### Scenario: 重复投递

- **WHEN** 同一条发布事件被投递两次
- **THEN** 订阅方再次收到事件，平台侧状态不产生重复发布记录

### Requirement: 版本对比

系统 SHALL 支持对比同一 Agent 的两个版本，展示模型、Prompt、工具版本绑定与运行策略的差异。

#### Scenario: 对比两个版本

- **WHEN** 开发者选择版本 1 与版本 4 对比
- **THEN** 系统返回资源绑定与策略参数的差异结果
