# Proposal

## Why

「用户用自然语言描述需求，模型自己构造参数调用工具」这条链路目前跑不通，而且失败不可归因。一次实测调用（同一 run，三次尝试）暴露了四个相互独立的断点：

- 模型收到的工具卡没有用途描述，参数只有 `title`，没有格式与示例；
- 参数校验失败了，但字段路径与原因在适配层被丢弃，只剩一句 `request validation failed`；
- 工具返回失败即终止整次执行，模型没有第二次改参的机会；
- 模型不知道当前日期，把「明天」当字面量传给日期参数，失败后改用 2025 年重试。

因此每新增一个工具，都要在 Prompt 里手写一段参数说明；工具语义滞留在 Prompt 里，无法随工具复用。本次变更把工具语义还给工具契约、把纠错回路还给模型、把运行时事实变成显式声明，使工具数量增长不再要求 Prompt 增长。

## What Changes

**工具契约成为模型可见事实**

- 工具版本上的「面向模型描述」与参数级 `description` / `format` / 示例随快照进入模型工具卡，模型据此构造参数而不是靠猜。
- 远端 MCP 探测得到的参数表允许在平台侧补全（模型可见契约与远端调用契约分离），不要求改远端服务。
- 工具版本可声明返回语义，区分「业务终态」（如无数据）与「可恢复失败」，使模型知道何时应如实告知用户而不是换参数重试。

**工具失败结构化回灌**

- 参数校验失败返回字段路径与原因，而不是笼统的校验失败文案。
- 可恢复失败以工具消息回到模型，模型在既有预算内自行改参重试；不可恢复失败与业务终态直接收敛。
- **BREAKING**：工具调用失败不再必然终止整次执行。原先一次工具报错即整次运行为失败，现在按可恢复性分流，最终结果仍受步骤与 Token 预算约束。

**运行时上下文声明式依赖**

- Agent 版本可声明所需运行时上下文（当前时间、时区、区域设置等），随版本固化进快照并参与配置摘要与版本对比。
- 平台按声明生成运行时上下文消息注入本次执行，值由服务端产生，不接受调用方传入，避免被请求体伪造。
- 未声明的上下文不会出现在 Prompt 中，依赖关系可查询而不是藏在提示词文本里。

**可观测**

- 模型调用记录保留本次工具卡摘要与工具调用轮次，使「模型实际看到了什么」可直接复核，而不必从代码反推。

## Capabilities

### New Capabilities

无新增能力。本变更修改既有能力的规格行为。

### Modified Capabilities

- `catalog/tool-registry`: 工具注册与版本契约的规格新增「面向模型描述必须进入模型工具卡」「参数级描述与格式必须可声明并被校验」「远端参数表可在平台侧补全」「工具版本可声明返回语义」。
- `agent/agent-release`: 版本生成与快照新增「运行时上下文依赖声明」，并纳入配置摘要、版本对比与引用校验。
- `execution/agent-invocation`: 工具调用失败的处理从「终止执行」改为「按可恢复性分流并结构化回灌」，并新增「按版本声明注入运行时上下文」。
- `insight/execution-trace`: 模型调用记录新增工具卡摘要与工具调用轮次，用于复核模型输入。

## Impact

- 代码：`contexts/agent/application/agent_service.py`（快照装配）、`contexts/catalog/domain/tool.py` 与 `tool_service.py`（契约校验与错误详情）、`contexts/execution/runtime/nodes.py`（上下文注入与失败分流）、`contexts/execution/infrastructure/tool_adapter.py`（错误映射保留详情）、`contexts/execution/infrastructure/tracing.py`（调用记录），以及对应的控制台接口与前端展示。
- 数据：工具版本与 Agent 版本快照新增可选字段；模型调用记录新增工具卡摘要。历史版本按快照冻结，不回填。
- 兼容性：已发布的历史版本保持原行为（无描述、失败即终止），新保存的版本才获得新语义；工具失败处理变化会影响依赖「报错即失败」的上层调用方。
- 风险：错误回灌会带来额外的模型回合，需在既有预算内控制重试次数，避免放大 Token 消耗。
