# Spec Delta

## ADDED Requirements

### Requirement: 工具失败的结构化回灌

执行过程中工具调用失败时，系统 SHALL 先按失败的可恢复性分流，再把结果回灌给模型，而不是直接终止整次执行。

- 可恢复失败（参数不符合契约、外部服务暂时不可用、超时）MUST 以工具结果消息回到模型，正文包含失败分类与可定位到参数或原因的信息，使模型能够修正后重新发起调用。
- 不可恢复失败（未授权、高风险被拦截、工具契约损坏）MUST 终止执行并返回明确原因，不得进入重试循环。
- 业务终态结果 MUST 以成功状态回灌，正文说明该结果不可通过更换参数改变。
- 回灌 MUST 受既有步骤与 Token 预算约束；预算耗尽时按预算耗尽失败结束，不得无限重试。
- 每次回灌 MUST 在执行记录中留下可追溯的失败分类，使最终成功的执行仍能看出曾经发生过工具失败。

#### Scenario: 参数错误被模型纠正

- **WHEN** 模型给出的参数不符合工具契约，工具返回字段级错误
- **THEN** 该错误作为工具结果回到模型，模型在预算内修正参数并重新调用，无需外部干预

#### Scenario: 业务终态不被当作错误重试

- **WHEN** 工具以业务终态返回「无数据」
- **THEN** 模型收到可读的终态说明，并据此直接回答用户，而不是更换参数反复调用

#### Scenario: 不可恢复失败终止执行

- **WHEN** 工具因未授权或高风险被拦截而失败
- **THEN** 系统终止执行并返回该失败原因，不把该错误回灌给模型重试

#### Scenario: 回灌受预算约束

- **WHEN** 连续的工具失败回灌使步骤数达到上限
- **THEN** 系统按步骤上限终止执行，返回预算耗尽结果

#### Scenario: 失败被纠正后仍留痕

- **WHEN** 一次执行中工具先失败后被模型纠正并最终成功
- **THEN** 执行记录仍保留那次失败的工具调用与其分类

### Requirement: 运行时上下文注入

执行时系统 SHALL 按 Agent 版本的运行时上下文依赖声明，在发送给模型的消息中注入对应上下文。注入内容 MUST 由服务端生成，MUST NOT 出现在调用方可写的输入中。

- 注入 MUST 在 Prompt 渲染之后进行，不得要求 Prompt 模板为上下文项声明占位符。
- 注入的消息 MUST NOT 被写入会话历史，以免按轮次累积。
- 同一轮执行内多次模型调用 MUST 使用同一份上下文取值，跨轮执行才重新取值。

#### Scenario: 相对时间可被解析

- **WHEN** 版本声明了时间上下文，用户输入「明天的天气」且工具参数要求 `YYYY-MM-DD`
- **THEN** 模型收到的上下文包含当前日期，使其能够把「明天」换算为具体日期

#### Scenario: 不污染会话历史

- **WHEN** 同一会话连续执行两轮且都声明了时间上下文
- **THEN** 后续轮次的历史中只保留各轮的用户与助手消息，不含上一轮注入的上下文

#### Scenario: 轮内取值稳定

- **WHEN** 一次执行中模型在一轮内发起多次工具调用
- **THEN** 这些调用看到的上下文取值一致，不因执行耗时跨过时间边界而变化

## MODIFIED Requirements

### Requirement: 执行记录

每次受理的调用 SHALL 创建一条运行记录，固定记录租户、Agent、发布记录、版本、调用者与追踪标识，并记录开始与结束时间、状态。

#### Scenario: 调用成功后的记录

- **WHEN** 一次调用成功返回
- **THEN** 该运行记录状态为成功且可追溯其发布记录与版本身份

#### Scenario: 调用失败后的记录

- **WHEN** 一次调用因模型错误、工具错误或预算上限失败
- **THEN** 运行记录保留失败状态与可读的失败原因分类

#### Scenario: 工具失败后仍成功的记录

- **WHEN** 一次执行中的工具调用先失败、经回灌后由模型纠正并最终成功
- **THEN** 运行记录状态为成功，且仍可查看到那次工具失败及其分类
