# Spec Delta

## ADDED Requirements

### Requirement: 工具卡对模型可见且自描述

工具版本 SHALL 向模型提供一份工具卡，包含用途描述与参数契约。用途描述 MUST 来自工具版本契约，不得为空。参数契约 MUST 在为每个参数保留类型的同时携带该参数的含义说明；日期、时间、枚举等取值受约束的参数 MUST 声明取值格式或可选值。

工具卡是平台生成的模型输入，SHALL 与远端实现解耦：当远端 `MCP` 服务返回的参数契约缺少说明或格式时，平台 SHALL 允许在工具版本上补全这些内容，补全结果随版本固化，不要求远端服务变更。

- 用途描述缺失的工具版本 MUST NOT 被保存。
- 未声明格式的日期类参数 MUST 被视为契约不完整，由保存时的校验指出。

#### Scenario: 工具卡携带用途描述

- **WHEN** 一个声明了用途描述的工具版本被 Agent 版本引用并进入执行
- **THEN** 本次执行中模型收到的工具卡包含该用途描述，而不是空描述

#### Scenario: 参数带含义与格式

- **WHEN** 工具版本声明了日期参数并标注格式为 `YYYY-MM-DD`
- **THEN** 模型收到的工具卡中该参数同时包含类型、含义说明与格式约束

#### Scenario: 补全远端缺失的参数说明

- **WHEN** 从远端 `MCP` 服务探测到的参数只有类型与标题，没有含义说明
- **THEN** 平台允许在不修改远端服务的前提下为该工具版本补充参数说明与格式，补充后的内容进入新版本的工具卡

#### Scenario: 用途描述为空被拒绝

- **WHEN** 提交的工具版本未提供用途描述
- **THEN** 系统拒绝保存，并指明缺失的字段

### Requirement: 工具返回语义可声明

工具版本 SHALL 能够在契约中声明本次调用结果的语义类别，至少区分「业务终态」与「可恢复失败」。业务终态表示工具已正确执行且没有更多可获取的数据，调用方不应通过更换参数重试；可恢复失败表示参数或外部条件可改变，允许重新发起调用。

- 声明为业务终态的结果 MUST 以成功的调用状态返回，其正文 MUST 向模型表明该结果不可通过重试改变。
- 声明为可恢复失败的结果 MUST 携带可供模型修正所需的结构化信息。

#### Scenario: 无数据作为业务终态

- **WHEN** 工具对合法参数返回空结果，且该工具版本把空结果声明为业务终态
- **THEN** 调用被记录为成功，返回正文向模型说明这是终态、不要换参数重试

#### Scenario: 可恢复失败携带结构化信息

- **WHEN** 工具因参数不符合契约而失败
- **THEN** 返回正文包含失败分类与可定位到具体参数的描述，供模型修正参数

## MODIFIED Requirements

### Requirement: 入出参契约与前置校验

每个工具版本 SHALL 声明输入与输出的 JSON Schema，并在输入契约中为每个参数提供含义说明。执行前的参数校验必须在发起外部请求之前完成。校验失败时，系统 MUST 返回可定位到具体参数与具体原因的错误，不得只返回笼统的校验失败文案。

#### Scenario: 参数合法

- **WHEN** 以符合 Schema 的参数调用工具
- **THEN** 系统发起外部请求并返回符合输出 Schema 的结果

#### Scenario: 参数非法被拦截

- **WHEN** 缺少必填参数或参数类型不符
- **THEN** 系统返回参数校验错误，且不发起任何外部请求

#### Scenario: 校验失败可定位到参数

- **WHEN** 某参数取值不符合声明的格式约束
- **THEN** 系统返回的错误包含该参数的路径与不符合的具体原因，而不是仅返回校验失败的状态

#### Scenario: 输出不符合契约

- **WHEN** 外部服务返回的结构不符合输出 Schema
- **THEN** 系统将本次调用标记为失败并保留原始响应的摘要供排查
