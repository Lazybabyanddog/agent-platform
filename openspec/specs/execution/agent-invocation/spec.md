# Agent Invocation Specification

## Purpose

提供同步调用 Agent 的统一入口，并保证一次执行只使用调用开始时确定的那一份发布快照，在步骤数、超时与 Token 预算的硬约束下产出可解释的结果。

## Requirements

### Requirement: 同步调用入口

系统 SHALL 提供同步调用接口，接收 Agent 标识、环境、输入与可选会话标识。调用开始时解析该环境的发布指针并固定发布记录与版本标识。

#### Scenario: 成功调用已发布 Agent

- **WHEN** 调用方以合法输入调用 PROD 环境已发布的 Agent
- **THEN** 系统返回执行结果、运行标识与追踪标识

#### Scenario: 目标环境无发布

- **WHEN** 调用方调用的环境尚无发布指针
- **THEN** 系统返回未找到发布的结果，不执行任何 Agent 逻辑

#### Scenario: 调用未授权 Agent

- **WHEN** 调用方对该 Agent 无调用权限
- **THEN** 系统返回无权限结果，且不创建执行记录

### Requirement: 输入校验与错误契约

系统 SHALL 在受理调用时按 Agent 版本的输入声明校验入参。校验失败必须返回可定位到具体字段的错误，且不产生执行记录。

#### Scenario: 缺少必填输入

- **WHEN** 调用方未提供版本声明的必填输入项
- **THEN** 系统返回指出该字段的校验错误

#### Scenario: 输入类型不符

- **WHEN** 调用方提供的输入类型与声明不符
- **THEN** 系统拒绝受理并返回类型错误

### Requirement: 按快照执行

执行 MUST 只使用调用开始时固定的版本快照内容。执行期间被引用资源产生新版本或被修改，均不得影响本次执行。

#### Scenario: 执行期间发布新版本

- **WHEN** 某次执行进行中该 Agent 发布了新版本
- **THEN** 本次执行仍按原版本快照完成

#### Scenario: 执行期间上游资源变更

- **WHEN** 执行过程中被引用的 Prompt 生成新版本
- **THEN** 本次执行继续使用快照中记录的旧版本内容

### Requirement: 执行预算与超时

系统 SHALL 对每次执行施加最大步骤数、总超时与 Token 预算。任一上限触发时，执行必须被终止并返回明确标识上限类型的失败结果。

#### Scenario: 超出步骤上限

- **WHEN** 执行步骤数达到版本声明的最大步骤数仍未结束
- **THEN** 系统终止执行并返回步骤上限导致的失败结果

#### Scenario: 超出总超时

- **WHEN** 执行耗时超过声明的总超时
- **THEN** 系统终止执行并返回超时失败结果，保留已产生的调用记录

#### Scenario: Token 预算耗尽

- **WHEN** 累计 Token 用量达到声明的预算上限
- **THEN** 系统终止执行并返回预算耗尽导致的失败结果

### Requirement: 工具调用的服务端二次授权

执行过程中发起的工具调用 MUST 在服务端按当前租户、用户与资源配置重新判定权限，不得仅以模型决定调用为授权依据。

#### Scenario: 模型请求未授权工具

- **WHEN** 模型在推理中选择了一个当前租户未获授权的工具
- **THEN** 系统拒绝该工具调用并把失败原因写入执行记录，执行按失败或降级策略继续

### Requirement: 执行记录

每次受理的调用 SHALL 创建一条运行记录，固定记录租户、Agent、发布记录、版本、调用者与追踪标识，并记录开始与结束时间、状态。

#### Scenario: 调用成功后的记录

- **WHEN** 一次调用成功返回
- **THEN** 该运行记录状态为成功且可追溯其发布记录与版本身份

#### Scenario: 调用失败后的记录

- **WHEN** 一次调用因模型错误、工具错误或预算上限失败
- **THEN** 运行记录保留失败状态与可读的失败原因分类

### Requirement: 长耗时调用引导异步

当请求声明的执行上限超过同步接口可受理阈值时，系统 SHALL 在受理阶段拒绝并提示改用异步执行能力，而不是在请求中途超时。

#### Scenario: 超过同步阈值

- **WHEN** 调用方请求的执行超时超过同步受理上限
- **THEN** 系统拒绝受理并返回提示改用异步接口的错误码，不创建运行记录

### Requirement: 用户输入作为对话消息进入执行上下文

系统 SHALL 在每次执行时把本次输入呈现为一条用户消息，使其进入该次执行的消息序列并随会话上下文留存，使模型能够看到本次输入，并使该轮在会话中可被定位为一个独立轮次。

- 当渲染后的模板消息已包含用户消息时，系统 MUST NOT 重复追加用户消息。
- 模板未引用输入中的变量时，系统 MUST NOT 因此丢弃输入。
- 系统提示词 MUST 每轮重新渲染，MUST NOT 在会话上下文中重复累积。

#### Scenario: 模板未引用输入变量

- **WHEN** 会话使用的模板只包含系统提示词，输入中的变量未被任何模板消息引用
- **THEN** 该次执行的消息序列仍包含一条携带本次输入内容的用户消息，模型据此回答

#### Scenario: 模板已包含用户消息

- **WHEN** 模板的用户消息引用了输入变量并已渲染出该轮提问
- **THEN** 系统不再追加额外的用户消息，消息序列与模板渲染结果一致

#### Scenario: 多轮延续

- **WHEN** 同一会话执行第二轮
- **THEN** 第一轮的用户消息与回答仍在本次执行的上下文中，模型可引用

#### Scenario: 未使用会话标识的调用

- **WHEN** 调用方未提供会话标识
- **THEN** 用户消息只存在于本次执行，不写入任何可回放的会话上下文
