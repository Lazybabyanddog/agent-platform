# Agent Session Specification

## Purpose

为预览会话保留可辨识的元数据与生命周期规则：标题、轮数、创建者随对话更新，使会话列表无需回读历史即可辨识，并让过期会话在标识被复用前仍可被访问。

## Requirements

### Requirement: 会话可辨识元数据与归属

会话 SHALL 记录可辨识标题、轮数与创建者。标题 SHALL 取自首轮用户输入的截断摘要；正文留存未开启时 MUST NOT 落标题正文。轮数 SHALL 在每一轮成功受理后递增。这些元数据 SHALL 供会话列表查询直接使用，MUST NOT 要求列表为每一行回读会话历史。

#### Scenario: 首轮建立标题与轮数

- **WHEN** 用户以「帮我梳理一下退款流程」开始一个新的预览会话
- **THEN** 该会话记录标题为这句输入的截断，轮数为 1

#### Scenario: 后续轮次递增

- **WHEN** 同一会话又完成两轮对话
- **THEN** 该会话轮数变为 3，最近活动时间随之更新

#### Scenario: 正文留存未开启

- **WHEN** 租户未开启正文留存，用户开始新会话
- **THEN** 该会话不记录标题正文，列表以环境、时间与轮数标识该会话

### Requirement: 过期会话的记录保留

会话过期后其记录 SHALL 继续保留，仅在该会话标识被重新用于发起新对话时才按新会话处理；MUST NOT 在过期瞬间清理记录，使历史失去访问入口。过期会话 MUST NOT 接受新消息。

#### Scenario: 过期后仍在列表中

- **WHEN** 一个会话超过保留期后再未被使用
- **THEN** 它仍出现在会话列表中并标记为过期，其历史仍可读取

#### Scenario: 标识被重新使用

- **WHEN** 调用方以已过期会话的标识发起新对话
- **THEN** 系统按新会话处理并重新绑定当前生效配置，旧记录不再作为该标识的会话
