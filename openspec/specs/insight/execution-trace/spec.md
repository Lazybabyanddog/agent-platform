# Execution Trace Specification

## Purpose

让一次 Agent 执行的模型调用、工具调用与失败原因可以被串起来查看，为问题定位、成本核算与后续评估提供可复用的运行事实。

## Requirements

### Requirement: 全链路追踪标识

每个受理的调用 SHALL 生成一个追踪标识，并在本次执行的模型调用、工具调用与审计事件中沿用同一标识。

#### Scenario: 从运行记录查看追踪

- **WHEN** 运维人员以某次运行标识查询追踪信息
- **THEN** 系统返回该次运行下的模型调用与工具调用条目，且均带同一追踪标识

#### Scenario: 追踪标识贯穿到审计

- **WHEN** 一次执行中发生了需要审计的操作
- **THEN** 对应审计事件包含该次执行的追踪标识

### Requirement: 模型调用记录

系统 SHALL 记录每次模型调用的模型标识、输入与输出 Token 数、耗时、状态与错误分类，并关联运行标识。

#### Scenario: 成功调用被记录

- **WHEN** 一次模型调用成功返回
- **THEN** 系统落一条记录，包含模型标识、Token 数与耗时

#### Scenario: 失败调用被记录

- **WHEN** 模型调用因限流、超时或供应商错误失败
- **THEN** 系统落一条失败记录并包含可区分的错误分类

### Requirement: 工具调用记录

系统 SHALL 记录每次工具调用的工具版本标识、参数摘要、耗时、状态与错误信息，敏感字段必须脱敏后落库。

#### Scenario: 工具调用成功

- **WHEN** 执行中某工具调用成功
- **THEN** 系统落一条记录，可定位到工具的确切版本

#### Scenario: 敏感参数脱敏

- **WHEN** 工具参数中包含被标记为敏感的字段
- **THEN** 落库与查询结果中该字段以掩码呈现

### Requirement: 追踪正文的落库与查看

系统 SHALL 在追踪记录中保留模型调用的完整请求消息与完整响应正文，作为排障与复盘的事实来源；工具调用的敏感字段 MUST 仍按参数 schema 脱敏后落库，凭据原文 MUST NOT 进入普通日志。

#### Scenario: 调用正文随追踪落库

- **WHEN** 一次模型调用结束（成功或因限流、超时、供应商错误失败）
- **THEN** 追踪记录包含该次调用的完整请求消息与响应正文，不需要任何租户级开关预先开启

#### Scenario: 敏感工具参数仍脱敏

- **WHEN** 工具参数中包含被标记为敏感的字段
- **THEN** 落库与查询结果中该字段仍以掩码呈现，与模型调用正文的保留策略无关

#### Scenario: 无权限者只见摘要

- **WHEN** 调用方不具备正文查看权限
- **THEN** 追踪接口只返回内容摘要与长度，不返回完整正文与完整响应

### Requirement: 运行指标可查询

系统 SHALL 支持按租户与 Agent 聚合查询调用量、成功率、失败率与耗时分布。

#### Scenario: 按 Agent 查看成功率

- **WHEN** 运维人员查询某 Agent 在时间范围内的运行情况
- **THEN** 系统返回调用量、成功与失败数量以及延迟分位值

#### Scenario: 定位最慢步骤

- **WHEN** 运维人员查看某次失败的运行
- **THEN** 系统返回各步骤耗时，可识别最耗时或失败的步骤
