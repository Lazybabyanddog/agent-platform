# Agent Debugging Console Specification

## Purpose

让调试台成为一次调试对话的完整工作区：可在会话之间切换、回放历史轮次，并在原配置下继续对话，回放本身不产生新的执行。

## Requirements

### Requirement: 调试会话列表与切换

调试台 SHALL 展示当前 Agent 的会话列表，并允许在会话之间切换。新建会话 MUST NOT 删除、隐藏或使既有会话不可访问；列表 SHALL 标出当前选中会话、轮数、最近活动时间与过期状态。列表为空时 SHALL 给出可执行的新建入口，列表加载失败时 SHALL 可重试且不影响已打开的对话。

#### Scenario: 新建会话后切回旧会话

- **WHEN** 用户在当前会话中对话若干轮后点击新建会话，随后在列表中选择旧会话
- **THEN** 旧会话与其全部轮次重新出现在对话区，新建的会话同时保留在列表中

#### Scenario: 切换 Agent

- **WHEN** 用户把调试台的 Agent 切换为另一个 Agent
- **THEN** 列表只展示该 Agent 的会话，原 Agent 的会话不会被删除

#### Scenario: 列表加载失败

- **WHEN** 会话列表请求失败
- **THEN** 列表区域展示失败原因与重试入口，正在进行中的对话不受影响

### Requirement: 历史会话回放

选中历史会话时，调试台 SHALL 渲染该会话的全部轮次——用户提问、模型回答、该轮工具调用条目——顺序与原对话一致，并允许查看单轮执行轨迹。回放 MUST NOT 触发任何执行，MUST NOT 产生运行记录。正文留存未开启时 SHALL 只展示轮次结构、长度与工具摘要。

#### Scenario: 回放含工具调用的历史

- **WHEN** 用户打开一个历史上调用了工具的会话
- **THEN** 每一轮按原顺序展示提问、回答与该轮工具条目，条目带工具名称与状态

#### Scenario: 回放不产生执行

- **WHEN** 用户连续打开三个历史会话
- **THEN** 三个会话的运行记录数量都没有增加

### Requirement: 恢复会话后的续聊约束

在历史会话中继续发送消息 SHALL 复用该会话首轮固化的配置与上下文，并沿用其会话标识。配置已变更时 SHALL 提示该会话仍使用首轮配置；会话已过期时 MUST 禁止发送并提示新建会话，而不是静默新建。

#### Scenario: 在历史会话中续聊

- **WHEN** 用户在昨天创建的会话中继续发送消息，而期间配置已被修改
- **THEN** 该轮仍按首轮配置执行，界面提示配置未生效并可新建会话

#### Scenario: 过期会话发送被阻止

- **WHEN** 用户在过期会话的输入框中尝试发送消息
- **THEN** 发送入口不可用或发送被拒绝，并提示新建会话，历史展示保持不变

### Requirement: 回放视图的稳定装载

调试台把当前 Agent、环境与会话标识同步到地址栏时 MUST NOT 导致对话视图卸载重建；已展示的轮次、未发送的输入与列表状态 MUST 在同步前后保持不变。

- 历史读取返回空轮次而对话区已有轮次时，SHALL 保留既有轮次。
- 会话声明存在轮次但历史无法解析时，SHALL 给出可解释的提示与重试入口，MUST NOT 呈现为空白对话区。

#### Scenario: 首轮结束后同步会话标识

- **WHEN** 新会话首轮完成，调试台把该会话标识写入地址栏
- **THEN** 对话区仍显示这一轮提问与回答，不出现空白，输入框内容与选中状态不被清空

#### Scenario: 在会话之间切换

- **WHEN** 用户在会话列表中选择另一个会话
- **THEN** 对话区替换为目标会话的轮次，列表的分页、选中项与滚动位置不被重建

#### Scenario: 历史为空但本地已有轮次

- **WHEN** 历史接口返回空轮次，而对话区已展示该会话刚完成的轮次
- **THEN** 已展示的轮次保持不动，并提示历史暂不可读

#### Scenario: 带会话标识刷新页面

- **WHEN** 用户带着地址栏中的会话标识刷新调试台
- **THEN** 恢复该会话并渲染其轮次；无法解析出轮次时给出提示与重试入口，而不是空白对话区
