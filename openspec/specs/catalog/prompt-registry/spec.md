# Prompt Registry Specification

## Purpose

把 Prompt 作为带类型变量与不可变版本的可复用资产来管理，使模板渲染结果可预期、线上执行可追溯到确切版本。

## Requirements

### Requirement: 多角色消息模板

系统 SHALL 支持由一条或多条消息组成的 Prompt 模板，每条消息声明角色（system、developer、user、assistant）与内容。

#### Scenario: 创建多消息模板

- **WHEN** 开发者提交包含 system 与 user 两条消息的模板
- **THEN** 系统保存模板并在预览时按声明顺序输出消息序列

#### Scenario: 非法角色被拒绝

- **WHEN** 模板中出现不受支持的消息角色
- **THEN** 系统拒绝保存并返回可定位到该消息的错误

### Requirement: 变量 Schema 与渲染校验

系统 SHALL 为模板变量声明名称、类型、是否必填与默认值。渲染时缺失必填变量或类型不符必须返回可定位的校验错误，不得产出残缺消息。

#### Scenario: 变量齐全时渲染

- **WHEN** 以包含全部必填变量的输入渲染模板
- **THEN** 系统返回替换后的完整消息序列

#### Scenario: 缺失必填变量

- **WHEN** 渲染时缺少某必填变量
- **THEN** 系统返回指出变量名称的校验错误，且不返回部分渲染结果

#### Scenario: 变量类型错误

- **WHEN** 以字符串传入声明为数值的变量
- **THEN** 系统返回类型校验错误

#### Scenario: 使用默认值

- **WHEN** 未传入声明了默认值的可选变量
- **THEN** 系统以默认值完成渲染

### Requirement: 不可变版本

Prompt 内容或变量声明发生变更 SHALL 产生新版本，版本号在同一 Prompt 内唯一且递增。已生成的版本内容不得原地修改。

#### Scenario: 修改后生成新版本

- **WHEN** 开发者基于现有版本修改消息内容并保存
- **THEN** 系统创建新版本，原版本内容保持不变

#### Scenario: 版本号重复被拒绝

- **WHEN** 两个请求同时尝试生成同一版本号
- **THEN** 仅一个成功，另一个收到冲突错误

### Requirement: 版本对比

系统 SHALL 支持对比同一 Prompt 的两个版本，展示消息内容与变量声明的差异。

#### Scenario: 对比两个版本

- **WHEN** 开发者选择版本 2 与版本 5 进行对比
- **THEN** 系统返回逐条消息与逐项变量的差异结果

### Requirement: 模板不得承载密钥

系统 SHALL 拒绝在模板内容中直接写入运行时密钥或凭据原文的保存请求。

#### Scenario: 模板包含疑似密钥

- **WHEN** 模板内容中出现疑似密钥字符串
- **THEN** 系统拒绝保存或明确标记高风险并要求确认，且不在日志中回显该字符串
