# Model Registry Specification

## Purpose

屏蔽不同模型供应商的接口差异，提供统一的模型注册、参数约束、连通性验证与基础限流能力，使执行层只面对平台内的统一模型契约。

## Requirements

### Requirement: 供应商接入

系统 SHALL 支持注册 OpenAI 兼容接口的模型供应商，配置项包含名称、Base URL、凭据引用与可用状态。供应商可属于平台级或指定租户。

#### Scenario: 注册供应商

- **WHEN** 管理员提交名称、Base URL 与凭据引用
- **THEN** 系统创建供应商记录并返回其标识与状态

#### Scenario: 停用供应商

- **WHEN** 供应商被停用后其下模型被调用
- **THEN** 系统拒绝调用并返回供应商不可用原因，不发起外部请求

### Requirement: 模型注册与标识分离

系统 SHALL 为每个模型分别保存平台内逻辑编码与供应商实际模型标识。模型必须声明上下文窗口、输入输出模态与能力标签。

#### Scenario: 注册模型

- **WHEN** 管理员在供应商下提交逻辑编码、实际模型标识与上下文窗口
- **THEN** 系统创建模型记录，二者分别存储且可独立查询

#### Scenario: 逻辑编码冲突

- **WHEN** 同一租户下提交已存在的模型逻辑编码
- **THEN** 系统拒绝创建并返回冲突错误

### Requirement: 参数模板与取值约束

系统 SHALL 为模型维护可配置的调用参数（如温度、采样、最大输出长度、超时）及其合法范围。超出范围的参数在保存或执行前必须被拒绝。

#### Scenario: 参数越界被拒绝

- **WHEN** 提交的温度值超出该模型声明的合法范围
- **THEN** 系统拒绝保存并返回可定位到该参数的校验错误

#### Scenario: 使用模型参数模板

- **WHEN** 执行时未显式覆盖参数
- **THEN** 执行使用该模型参数模板中的值

### Requirement: 连通性测试

系统 SHALL 提供模型连通性测试能力，测试结果必须区分成功与失败原因，且响应中不得出现凭据原文。

#### Scenario: 测试成功

- **WHEN** 管理员对某模型发起连通性测试且外部服务正常响应
- **THEN** 系统返回成功结果与耗时

#### Scenario: 测试失败

- **WHEN** 供应商返回认证失败或超时
- **THEN** 系统返回失败结果与错误分类，且不返回凭据原文

### Requirement: 基础限流

系统 SHALL 对模型调用施加租户级请求频率与并发上限。触发上限的调用必须被拒绝，且拒绝原因可区分于模型自身错误。

#### Scenario: 超出频率上限

- **WHEN** 某租户在统计窗口内的模型调用次数超过配置上限
- **THEN** 系统拒绝该次调用并返回限流错误，不发起外部请求

#### Scenario: 限流计数可恢复

- **WHEN** 统计窗口过去且并发释放
- **THEN** 该租户的后续调用被正常受理

### Requirement: 不可用模型失败关闭

当模型或其供应商处于停用、凭据不可用状态时，引用该模型的 Agent 发布与执行 MUST 失败关闭并给出明确原因，不得静默降级到其他模型。

#### Scenario: 发布引用停用模型

- **WHEN** 某 Agent 版本引用已停用的模型版本
- **THEN** 发布被拒绝并返回具体不可用原因

#### Scenario: 执行时模型被停用

- **WHEN** Agent 已发布，其引用的模型在之后被停用并被调用
- **THEN** 本次执行返回失败状态与原因，且不产生伪造的成功结果
